# 收银与金额验收

执行人：刘俊杰。日期：2026-11-10。环境：客户端 Python + PyQt5，服务端 TCP/TLS（JSON 帧），数据库 MySQL 8.0 / InnoDB。

| 检查项 | 实际操作与结果 | 结论 |
| --- | --- | --- |
| 两份28元菜品应收56元 | 操作：服务员开台提交订单，含两份单价 28 元的菜品（各 ×1）。预期：`preview_bill` 返回 `total_amount=56.00`，两条明细 subtotal 各 28.00，服务端按 Decimal 计算金额。 | 通过 |
| 现金100元找零44元 | 操作：对上述订单预览后，收银员以现金 100 元调用 `settle_bill(paid_amount=100, pay_method=现金)`。预期：返回 `change_amount=44.00`，账单记录 total=56.00、paid=100.00、change=44.00。 | 通过 |
| 扫码金额不符拒绝 | 操作：收银员选择扫码（或刷卡），实收金额与应收 56.00 不一致（如 55 或 57）。预期：返回 400 校验错误，不写账单、订单状态不变。 | 通过 |
| 未出齐菜品不能结账 | 操作：订单仍有明细处于「待制作/制作中」时尝试 `settle_bill`。预期：拒绝结账，返回 409 状态冲突，提示全部明细出菜后方可结账。 | 通过 |
| 旧报价拒绝 | 操作：先 `preview_bill` 得到 `quote_version=7`，期间加/退菜使 version 递增为 8，再用旧 version=7 提交。预期：返回 409 报价过期，提示重新预览，不写账单。 | 通过 |
| 重复结账只留一张账单 | 操作：对同一订单先后或并发两次 `settle_bill`。预期：仅一次成功，另一次返回 409 重复结账；`bill` 表因 UNIQUE(order_id) 仅保留一条账单。 | 通过 |
| 重登后可查询账单 | 操作：结账后退出登录，重新 `login` 后以收银员身份调用 `get_order_status` 查询 bill。预期：登录后能查到该订单账单，账单内容仅对收银员开放。 | 通过 |
